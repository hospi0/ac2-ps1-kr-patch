## 2. ACE2.DAT 구조

```
+0x000  u32 1 · u32 226(항목 수)
+0x008  226 × { u32 크기 | 플래그<<28 , u32 오프셋/512 }     ✅ 226개 전부 앞뒤가 이어짐(틈 < 512)
        목차가 덮는 범위 0x200 .. 0x173E3EF
+0x173E400 .. 끝(0x5CF9000)  ≈ 73.2 MB «목차 밖 꼬리»
```
- 플래그 2 = E000·E001 (나머지 0).
- ✅ **본체 EXE = DAT+0x800 의 PS-X EXE** (pc `0x8001CB50` · t_addr `0x80018000` · t_size `0xA1800`).
  파일→주소 `a = 0x80018000 + (f − 0x1000)`. 목차의 E000~E005 는 이 EXE 의 조각이다
  (E002=`0x80048800` · E003=`0x8006A000` · E004=`0x80089800` · E005=`0x8009FC00` — 주소 연속 + jal 표결 일치).
  `work/ACE2MAIN.EXE` 로 뽑음(`tools/mdis.py` 가 자동 생성).
- 🔸 꼬리 영역은 본체 EXE `0x800AD8EC` 의 오름차순 표(476개, DAT 기준 2048 B 단위, `0x2E7C`~)가 가리키는 것으로 보인다. 역할 ❓.
- 🔸 E078~E141 은 크기가 거의 같은 «3개 1조» (예 203,280 / 203,280 / 203,364) — 미션 팩 후보.
- TIM 13,117개 검출 (항목별로 흩어짐) — 구운 글자 후보는 미조사.

## 3. 글자 경로 — ✅ BIOS 한자 ROM

```
0x8009F248  Krom2RawAdd 썽크 (li t2,0xB0 ; jr t2 ; li t1,0x51)     jal 호출 2곳
  ├ 0x80065230 ∈ 0x80065220  16×15 1bpp → 4bpp 16×16(0x80 B, 잉크값 7) 변환
  │     호출자 ├ 0x80036B88  문자열 → 한 줄 띠(최대 0x1A B = 13자) → LoadImage(0x800A2250)
  │            ├ 0x80036C78  «무선 메시지» — 레코드표 gp+0xFD4(4 B) · 본문 = [gp+0x16B8] + idx×32
  │            │             한 메시지 최대 0x1A B = **전각 13자**  (호출자 44곳)
  │            └ 0x80099FDC  글자 캐시 256칸 (표 0x800BE668 · VRAM x=0x2C0+(칸&15)×4, y=0x100+(칸&0xF0))
  │                          ← 0x80099F70 문자열 훑기 (호출자 16곳)
  └ 0x80065450 ∈ 0x80065440  축소판(0x48 B) — 직접 jal 호출자 0 (함수 포인터 후보)
```
- ✅ **2바이트 판정은 선두 `0x80~0x9F` 뿐** (`0x80099F70`: `(b+0x80)&0xFF < 0x20`). `0xE0~` 은 1바이트 취급.
  ⇒ 한글 코드는 **`0x889F~0x9FFC`(한자 1수준 행)** 안에 배정해야 한다. 완성형 2,350자는 들어간다.
- ⇒ 테마 호스피탈 방식(썽크 호출 `jal` 을 내 루틴으로 돌려 한글 글리프 반환, `th-ps1-kr-patch/tools/thkr.py`)이 그대로 후보.
  한글 BIOS 방식(코드 주입 0)도 가능하나 사용자 BIOS 에 의존.
- 제어코드 흔적: 디버그 메뉴 `%F1%C7ROOT MENU` (의미 ❓), 줄바꿈 `0x0A`, 브리핑 줄 머리 `--`(들여쓰기 후보).

## 6. 추가 판정 (같은 날)

- ✅ **본체 EXE 문자열 포인터 census**: 텍스트 조각 186개(1,969자) 중 **173개가 u32 절대주소로 참조**, 3개는 lui/addiu 쌍,
  참조 없는 10개(22자)는 전부 잡음(글자 아님). ⇒ 본체 EXE 문장은 «옮기고 포인터 고치기»로 길이 제약을 풀 수 있다
  (여러 곳에서 참조하는 문장 있음: 「メモリーカードのエラーです。」 5곳 — 모든 참조를 같이 고칠 것).
- 🔸 **RAM 배치**: gp = `0x800B8E4C`, gp 상대 전역 `0x800B15CF..0x800C06DA`, 코드가 정적으로 참조하는 최고 주소 ≈ `0x800C1EE8`
  (그 위는 스택 `0x801FFFF0` 뿐). `0x800C2000..0x801C8000`(≈1MB)은 힙·미션 데이터 적재 영역 후보 — «비어 있다»는 증거 없음.
  폰트·루틴 자리는 세이브스테이트 RAM 을 여러 장면에서 떠서 판정해야 한다.

## 7. 세이브스테이트 5장 판정 (사용자 제공 `D:\hospi\duckstation\savestates\SLPS-00830_{1..5}.sav`)

도구: `tools/state.py`(스샷·RAM·VRAM) · `tools/ac2state.py`(여러 장 한꺼번에 → `work/state/<n>/`).

| # | 장면 | 글자 캐시 점유 | 본문 출처 (RAM → DAT) |
|---|---|---|---|
| 1 | 타이틀(START GAME/LOAD/OPTION) — 캐시엔 옵션 화면 문구 | 159/256 | 본체 EXE (E000+30C8 …) |
| 2 | 난이도 선택 (하단 도움말 「難易度：ふつう」) | 177/256 | 본체 EXE (E000+2000) |
| 3 | 오프닝 브리핑 (하단 자막 「直ちにクーデター軍鎮圧の任に」) | 176/256 | 본체 EXE (E000+2884 …) |
| 4 | 미션 브리핑 지도 (하단 「目標を…」) | 117/256 | **미션 팩 E020** (+D674 · +15394 두 벌, RAM 에도 두 벌) |
| 5 | 비행 중 — 무선 메시지가 **화면 오른쪽에 세로쓰기** | 117/256 | `[gp+0x16B8]`=0x80127998 ← **E154/E159/E163/E167/E169/E172/E175/E178 8벌 동일** |

- ✅ **사용자 DuckStation 은 한글 BIOS** — 화면에서 한자 자리가 한글로 찍힌다(「難易度」·「軍鎮圧」→한글 조각). 글자 캐시 VRAM
  (`x=0x2C0.., y=0x100..`)에도 같은 한글 글리프. ⇒ «본문 SJIS → BIOS 한자 ROM → 캐시 → 화면» 경로가 **실제 화면으로 증명**.
  (완성형 순서 한글 BIOS: 「가」=0x889F — [[reference_ps1_korean_bios_font]])
- ✅ 캐시가 차면(0x80099FDC: 빈 칸 못 찾음) 그 글자는 **안 굽고 넘어간다** → 화면에서 빈 칸/엉뚱한 글자. 한국어는 고유 음절이
  일본어 가나+한자보다 많아질 수 있어 **화면당 고유 음절 ≤ 256(여유 포함 목표 ~230)** 을 검사기로 걸어야 한다.
- 무선 메시지 레코드 4 B(`[gp+0xFD4]`): 우선순위 · 효과음 · 본문 번호 · 다음 메시지 (🔸코드 0x80036C78 과 일치하는 해석).
- 빈 RAM 후보(5장 모두 0이고 상태 간 불변):
  - `0x800C3000..0x800CF000` 48 KB — 정적 BSS 끝(≈0x800C1EE8) 바로 위. 비행 중에도 0.
  - `0x801DB000..0x801FA000` 124 KB — 단, 바로 아래 `0x801C8000..0x801DA000`(부트 로더 자리)는 상태 4·5에서 **힙으로 재사용** → 무거운 미션에선 더 올라올 수 있다.
  - ⛔ 둘 다 «안 쓴다»는 증명은 아님 — 힙 할당기 경계(코드)로 확정할 것.
- 영문 UI(타이틀 메뉴·「Play Level」·HUD·「Target: B-52 bomber unit」)는 원판부터 영어. 일본어는 하단 도움말·자막·무선 메시지·기체 설명 등.

## 8. 한글 폰트 배치 판정 (훅 방식, 2026-09-14)

### RAM 지도 (확정)
```
0x80010000..0x80012E30  영속 구조체 [0x800B8F74]=0x80010000 (필드 ~+0x154C · +0xE30 부터 세이브 이미지 8KB)
0x80012E30..0x80016800  ★빈 자리 ≈14.8KB — 5개 상태 모두 0, 본체·동영상 재생기·부트 어느 코드도 참조 안 함
0x80016800..0x80017718  부트 로더가 넘긴 파일 위치·DAT 목차 사본
0x80018000..0x800B9800  본체 EXE 이미지
0x800B9700..0x801FA800  ⛔ 시작 코드(0x8001CB50)가 통째로 0 으로 지움 (BSS + 적재 힙)
  적재 힙 = 0x800C1EE8+[gp+0xE9C] 부터 1MB(또는 1.125MB)  (할당기 0x80069D6C · 경계 설정 0x80069BAC)
  메뉴 0x800CF250..0x801CF250 · 격납고 0x800FB250..0x801FB250 · 비행 0x800D8418..0x801D8418
0x801FA804..            BIOS InitHeap 힙 → 스택(0x801FFFF0)
```
- ⛔ 앞서 후보였던 `0x800C3000..0x800CF000`(48KB)·`0x801DB000..0x801FA000`(124KB)은 **예약 버퍼·힙 한도 안**이라 탈락.
- 본체 죽은 코드(참조 0, `jr ra` 블록 기준): 5,476 B · 최대 468 B 조각 (`tools/deadcode.py`). ⛔prologue 를 머리로 믿으면 거짓양성
  (컴파일러가 `lw` 를 prologue 앞으로 당긴다 — 첫 census 17.8KB 는 틀렸다).
- DAT+0xA2800 의 둘째 PS-X EXE = **MDEC 동영상 재생기**(적재 0x80160000, 본체가 BIOS Exec 로 실행, 번역 문자열 없음).
  재생기는 낮은 영역 중 0x80010000·0x80016800 만 참조 → 빈 자리 안전.
- 오버레이 코드 없음(DAT 전체에서 본체 함수로 가는 jal 묶음 0).

### 블롭 싣는 경로 (설계안)
- 디스크 끝 **LBA 246,564..246,713 (150섹터, 300KB)** — STP 뒤, PVD 볼륨(246,714) 안, Form1·데이터 0·EDC 정상 → 파일 밖 빈 섹터.
- 여기에 «훅 루틴 + 조합형 부품 + 음절표»(≈10KB, 7섹터 이내)를 두고, **CdControl(Setloc)→CdRead→CdReadSync** 로 `0x80013000` 에 읽는다.
  (부트 로더 `0x801CF22C` 가 같은 순서로 파일 머리를 읽는다 — 부트 쪽 또는 본체 초기화 쪽 어디서 부를지는 PoC 에서 결정.
  부트 EXE 끝 0 여유 632B 는 부트 자신의 데이터라 ⛔.)
- 본체: Krom2RawAdd 썽크를 부르는 `jal` 2곳(`0x80065230`·`0x80065450`)을 루틴으로 돌린다. 한글 코드(0x889F~)가 아니면 원래 썽크로.
- 남는 낮은 영역은 길이가 늘어난 본체 EXE 문자열의 이주 자리로 쓸 수 있다(포인터 전수 교체).

## 11. 미션 브리핑 규격 확정 (2026-09-14, 코드 + 세이브스테이트 4)

```
미션 팩 안 «브리핑 하위 파일» (팩마다 1~2개, 본체 전역 0x800B9E00/04 가 가리킴 — 상태 4 = E020+0xCD6C / +0x14A8C)
  +0      u32 (영문 쪽 수 후보)
  +4      u32 N   일본어 칸 수 — 칸0 = 「제목」, 칸1..N-1 = 본문
  +8      영문 내레이션 쪽: +8 + 0x90×쪽 (144 B 쪽)  — 0x8008CDF4 · 번역 대상 아님
  +0x908  일본어 칸 k = +0x908 + 40×k (NUL 끝)   — 0x8008CA28 (선적재: 0x80099F70 에 칸마다) · 0x8008CCB0 (줄 그리기: 0x8008B15C)
```
- ✅ 칸 사이에 보이던 `-`×n · `+ C3` · `C6` 은 **저작 도구가 남긴 앞 칸 찌꺼기**(영문 쪽에는 x86 기계어 찌꺼기까지 있다) — 제어코드 아님.
  ⇒ 번역문은 칸마다 **NUL 포함 40 B 이하**(= 전각 19자), 남는 칸은 0 으로 채워도 된다(게임은 NUL 까지만 읽는다).
- 전수 (`tools/briefscan.py`, 판별 = `p+8`='[' 이고 `p+0x908`='「'): 하위 파일 **48개 → 고유 30블록 = 미션 30개**,
  고유 줄 **403 · 5,212자** · 최장 38 B. 칸 N 이 `END` 인 블록 28 (E052·E108 은 N=20 이고 칸 20 이 `END` 아님 — 게임은 k<N 만 읽으므로 무관).
- ⛔ 앞선 `--` 기준 추정(344줄·4,570자)은 찌꺼기에 휘둘린 틀린 값.
- 선적재가 **한 브리핑 전체**(칸 N개 × 하위 파일 2개)를 글자 캐시에 올린다 → 한국어 번역은 «브리핑 블록 + 그 화면 UI 문구» 고유 음절 ≤ 256 검사 필수.
